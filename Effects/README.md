# Effects

The effects this package ships, one folder per effect. **No effect exists yet**: this file keeps the
folder (git tracks no empty folder, and `check_metas.py` fails on a folder `.meta` without a
Unity-visible file in it).

## Layout of one effect

```
Effects/<Name>/
  <Name>.vfxrecipe.json   the recipe: the source of truth (schema Schemas~/vfx-recipe.schema.json)
  <Name>.vfx              the graph `build` makes from the recipe, next to it
  <Name>.prefab           a prefab with the VisualEffect (and, for a chain effect, a ChainLightningBinder),
                          the object a VfxLibrary entry points at
  <Name>_<Purpose>.png    textures brought in with `import-texture` (for example <Name>_Glow.png)
```

- `<Name>` is PascalCase (`ChainLightning`); the recipe's `id` is the kebab-case effect id
  (`chain-lightning`) that a `VfxLibrary` entry and `VfxPlayer.Play` use.
- Rebuild a `.vfx` only when its recipe changed: two builds of one recipe give different bytes and the
  same `describe` (Documentation~/AUTHORING.md, Pitfalls).
- Shared pieces used by several effects (subgraphs, gradients, textures, the grid shader of the
  Showcase and the capture stage) live in `Library/`, not here.
- Every file and folder here has its `.meta`, generated by Unity.

The authoring workflow is in [Documentation~/AUTHORING.md](../Documentation~/AUTHORING.md).
